WLAN AC 双机冷备 — 故障切换验证证据 (cold_failover2 + quick_state 实测)
采集时间: 2026-07-21 (AC1 Vlanif10 shutdown 后 ~150s)

=== 故障注入 ===
[AC1] interface Vlanif10 -> shutdown   (CAPWAP 源失效)
[AC1] display interface Vlanif 10 -> *down/down  (确认)

=== AC1 上 AP 状态 (主 AC 失效) ===
<AC1> display ap all
Total AP information:
fault: fault           [1]
idle : idle            [2]
ID   MAC            Name Group   IP Type            State STA Uptime
1    00e0-fc1b-3720 AP1  default -  AP3030DN        idle  0   -
2    00e0-fcdb-0400 AP2  default -  AP3030DN        idle  0   -
3    00e0-fcf8-32e0 AP3  default -  AP3030DN        fault 0   -
-> AP3 在 AC1 上变为 fault (隧道源失效)

=== AC2 上 AP 状态 (备 AC 接管) ===
<AC2> display ap all
Total AP information:
idle : idle            [2]
nor  : normal          [1]
ID   MAC            Name Group   IP         Type            State STA Uptime
3    00e0-fcf8-32e0 AP3  default 10.1.1.251 AP3030DN        nor   0   2M:46S
-> AP3 重新注册到 AC2，状态 normal，获得管理 IP 10.1.1.251

<AC2> display radio all
AP ID Name RfID Band  Type    ST  CH/BW          CE/ME STA CU
3     AP3  0    2.4G  bgn     on  6/20M          -/-  0   0%
3     AP3  1    5G    an11ac  on  149/20M        -/-  0   0%
-> 射频 0/1 均 up

<AC2> display vap all
AP ID AP name RfID WID BSSID          Status Auth type     STA SSID
3     AP3     0    1   00E0-FCF8-32E0 ON     WPA/WPA2-PSK  0   Office-Cold
3     AP3     1    1   00E0-FCF8-32F0 ON     WPA/WPA2-PSK  0   Office-Cold
-> VAP 状态 ON，SSID Office-Cold 正常广播

结论: 冷备切换成功 —— 主 AC1 故障后，AP3 在 ~150s 内重新发现并注册到备 AC2，
射频/业务 SSID 恢复正常广播。符合方案"冷备需手动在备 AC 添加 ap-id 后 AP 重新注册"的机制。
(AP1/AP2 因 eNSP AP telnet 控制台不可达，无法重启，始终 idle，未参与验证。)
